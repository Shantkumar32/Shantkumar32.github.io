CDR & IPDR Investigation

Learn Call Detail Records, IP Detail Records and network data analysis

1. What is CDR?

CDR stands for Call Detail Record. It contains information about telecommunications activity such as calls and SMS. A CDR normally contains metadata rather than the actual conversation content.

Common CDR Fields

  • Calling number / A-Party
  • Called number / B-Party
  • Date and time
  • Call duration
  • Call type
  • IMEI
  • IMSI
  • Cell ID
  • LAC / TAC
  • Network/operator information

2. What is IPDR?

IPDR stands for Internet Protocol Detail Record. It is network-related metadata that can help associate internet activity with a subscriber or connection, subject to the records provided by the service provider.

Common IPDR Fields

  • Subscriber/User ID
  • Public IP address
  • Source IP
  • Destination IP
  • Source port
  • Destination port
  • Protocol
  • Start time
  • End time
  • Upload volume
  • Download volume

3. CDR vs IPDR

CDR IPDR
Primarily telecom call/SMS activity Primarily internet/network activity
MSISDN is commonly important IP address and subscriber/session information are important
IMEI/IMSI may be available Ports and protocols may be available
Cell information may be available Destination IP information may be available

4. Important Subscriber Identifiers

MSISDN

MSISDN generally refers to the subscriber's telephone number.

IMSI

IMSI is an identifier associated with a mobile subscriber identity.

IMEI

IMEI identifies a mobile device/equipment.

Investigation concept: A telephone number, subscriber record and device identifier can provide different pieces of information and should not be treated as interchangeable identifiers.

5. IP Address Analysis

An IP address identifies a network endpoint or interface. During network-data analysis, investigators may examine the relationship between subscriber information, timestamps, source IP, destination IP and ports.

Important Questions

  • Who was assigned the IP address?
  • At what exact date and time?
  • Which subscriber/session was associated with it?
  • What destination IP was contacted?
  • Which destination port was used?
  • Which protocol was recorded?
  • How much data was transferred?

6. Port & Protocol Analysis

Network ports are logical endpoints used by applications and services. Protocol information can help understand the type of network communication recorded.

Protocol General Purpose
TCP Connection-oriented communication
UDP Connectionless communication
HTTP Web communication
HTTPS Encrypted web communication
DNS Domain name resolution

7. NAT / CGNAT Concept

Multiple users can sometimes share a public IPv4 address through Network Address Translation (NAT) or Carrier-Grade NAT (CGNAT).

Important: When investigating shared public IP addresses, timestamp, source-port information and provider records may be important for distinguishing different subscribers or sessions.

8. Upload & Download Analysis

IPDR records may contain traffic-volume information. Upload and download volumes can be compared to understand the recorded direction and amount of traffic.

  • Upload bytes
  • Download bytes
  • Total bytes
  • Session duration
  • Traffic direction
Example:

Upload = 50 MB
Download = 500 MB

This indicates considerably more recorded downstream traffic than upstream traffic during that session. It does not, by itself, establish what content was transmitted.

9. IPDR Investigation Workflow

Step 1 Obtain provider records
Step 2 Identify subscriber/session
Step 3 Verify timestamp
Step 4 Analyse IP addresses
Step 5 Analyse ports/protocols
Step 6 Correlate other evidence

10. Evidence Correlation

Network records should normally be analysed together with other relevant evidence rather than relying on a single IP address or port.

  • CDR
  • IPDR
  • Subscriber/KYC records
  • Device information
  • Application logs
  • Server logs
  • Transaction records
  • Digital forensic findings
